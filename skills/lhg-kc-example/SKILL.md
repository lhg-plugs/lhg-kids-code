# lhg-kc-example：积木逻辑说明与趣味示例规范

> **安全声明（必读）**：本 skill 是**家长/老师的备课助手**，不直接面向儿童。
> 所有示例代码**必须由成年人先运行验证**，再用于课堂；本插件**不收集任何儿童信息**。

> 目标：示例要"小到一眼看懂、大到值得玩"，且**在课堂上一次跑通**。
> 核心纪律：**只用已教过的概念；每段代码都能运行；注释是给孩子看的第二份讲稿。**

## 1. 何时使用

- 教案需要 Scratch 积木步骤说明时 → 用第 3 节
- 教案需要 Python 趣味示例时 → 用第 4 节
- 检查一段示例是否"课堂就绪"时 → 用第 8 节清单

## 2. 输入与输出

- **输入**：概念 + 年龄段 + 工具（Scratch / Python）+ 已教概念清单
- **输出**：积木步骤说明（中文积木名 + 运行效果）或 Python 代码块（可运行 + 逐行中文注释）+ 课堂讲解话术要点

## 3. Scratch 积木逻辑说明规范

1. **中文积木名**：用"当绿旗被点击""重复执行 10 次""如果…那么"这类中文描述，不写英文原名（低龄段）；高龄段可在括号备注英文。
2. **一次 3-5 块**：单次讲解的积木不超过 5 块，多了就拆成两次"预测-运行"。
3. **顺序三问**：每块积木讲清三句话——"它在什么时候动（事件）""它管什么（控制）""它让角色做什么（动作）"。
4. **配运行效果**：每组积木后写一行"运行后你会看到：……"，让老师有预期。
5. **先搭后讲**：话术顺序是"我们先把这几块拼起来，点绿旗看看"，而不是先讲定义。

积木描述格式示例：

```text
当绿旗被点击
重复执行 10 次
└移动 10 步
└如果碰到边缘就反弹
运行后你会看到：小猫来回走 10 次，碰到边就掉头。
```

## 4. Python 趣味示例规范（turtle 优先）

1. **turtle 优先**：有画面反馈（画图），孩子"看得见"程序在干嘛；纯 print 示例只用于 11 岁以上第一课。
2. **≤30 行**：含注释不超过 30 行，超了就拆成"基础版 + 加料版"。
3. **逐行中文注释**：每 1-3 行配一句中文注释，注释说"这行在干嘛"，不说术语。
4. **只用已教概念**：示例里出现的所有语法必须在"已教概念清单"里；要用新东西，先在教案里安排教学。
5. **必须可运行**：Python 3，零第三方依赖（只用标准库 turtle / random / time）。
6. **输入输出看得见**：要么画出图，要么打印出孩子能念出来的话。
7. **结尾收口**：turtle 示例末尾加 `turtle.done()`，并注释"点一下小乌龟窗口的叉才能关"。

示例（讲循环，8-10 岁，已教：for、turtle 基础）：

```python
import turtle # 请出画画的小乌龟

turtle.speed(6) # 小乌龟跑快一点，不然我们要等很久
turtle.pencolor("blue") # 拿起蓝色的画笔

for i in range(4): # 复读机说：下面两行，做 4 遍
turtle.forward(100) # 往前爬 100 步
turtle.right(90) # 向右转一个直角弯

# 你看到了吗？4 条一样长的边，一个正方形！
turtle.done() # 画完了，窗口留着给我们看
```

## 5. 积木 ↔ 代码对照（原创整理，跨工具过渡时用）

| Scratch 积木（中文） | Python 对应 | 讲法提示 |
|---|---|---|
| 当绿旗被点击 | 程序从上往下跑 | "绿旗就是发令枪" |
| 重复执行 N 次 | `for i in range(N):` | 先讲积木版，再指着代码说"这是同一件事的另一种写法" |
| 如果…那么…否则 | `if …: else:` | 用红绿灯类比过渡 |
| 将…设为… | `x = …` | "收纳盒换标签" |
| 说…2 秒 | `print(…)` | "小猫说话 → 电脑说话" |

过渡原则：**先积木后代码**，同一概念两种写法对照讲，不许跳过积木直接上代码（11 岁以下）。

### 5.1 Scratch 完整示例（讲"条件分支"，8-10 岁）

```text
【积木 1】当绿旗被点击
【积木 2】将"分数"设为 0
【积木 3】重复执行 10 次
  └【积木 4】将"分数"增加 1
  └【积木 5】如果"分数" > 5，那么
      └【积木 6】说"你过半啦！"2 秒
运行后你会看到：小猫从 1 数到 10，数到 6 时突然说话"你过半啦！"。
```

讲解话术要点：
- 先搭积木 1-4，点绿旗，让孩子看"它只会数数"。
- 提问："我们想让它数到一半时说句话，加哪块积木？"→ 引出积木 5-6。
- 顺序三问示范（积木 5）："它在什么时候动？（每次加完分之后）它管什么？（管'说不说话'这个决定）它让角色做什么？（分数大于 5 就说话）"

## 6. 第二个 Python 示例（讲"变量"，11-13 岁，已教：变量赋值、input、print）


```python
box = "积木"  # 拿一个收纳盒，贴上名字"盒子"，里面放"积木"
print("盒子里现在是：" + box)  # 打开盒子看看

box = "小汽车"  # 把积木拿出来，换成小汽车，盒子名字不用换
print("盒子里现在是：" + box)  # 再打开看看，变了！

name = input("你的小名是？")  # 问小朋友一个问题，把回答装进"名字"盒子
print("你好呀，" + name + "！盒子记住你啦")
```

课堂讲解要点：
- 每行讲完立刻指着屏幕问"盒子里现在是什么？"，让孩子抢答。
- 教学点：变量名不变、里面东西可变——"收纳盒换内容不换标签"。
- 注意：`input` 需要键盘，网课/录播场景改用固定值 `name = "小明"`，
  并在教案"运行"环节注明，避免课堂冷场。

## 7. 常见课堂坑与备课预案

| 坑 | 预案（写进教案"运行"环节） |
|---|---|
| 无限循环卡死 | 只用 `range(N)` 版循环；真卡了教"点红色八角形停止"，课前老师先试一次 |
| 中文标点进代码 | 示例里全角符号标红提醒；话术"代码只认半角符号" |
| turtle 窗口一闪而过 | 必须加 `turtle.done()`；备课时老师自己跑一遍确认 |
| 缩进报错 | 话术"冒号下面要空 4 格，像排队"；示例缩进统一 4 空格 |
| 孩子改数字改出 bug | 改写任务限定"只改数字不改结构"，并给"改坏了点这里恢复"（保留原代码注释版） |

## 8. 示例"课堂就绪"检查清单

1. 在本机 Python 3 下真实运行过一次（零报错）？
2. 行数 ≤30（含注释）？
3. 所有语法都在"已教概念清单"里？
4. 注释是中文、说"在干嘛"而不是背术语？
5. 运行效果孩子能直接看到（画图/说话）？
6. 有"改一处就能玩"的改写点（如改颜色、改次数）？
7. 附了"若运行不符预期先检查什么"？

7 条全过才能进教案。

## 9. 反模式（不要这么做）

- ❌ 一次性给 80 行"完整小游戏"——孩子看完只想抄，不想懂
- ❌ 示例用 `import` 一堆第三方库——课堂环境装不上就全废
- ❌ 注释写英文或术语（`# iterate over range object`）——注释是给孩子看的
- ❌ 代码里出现未教概念还不标注——等于埋雷
- ❌ 只给代码不给"运行后你会看到"——老师课堂上没预期会慌

## 10. 自检与反馈

每次写完示例后，做一次轻量自检：

1. 真实运行过吗？→ 没跑过的代码不许进教案。
2. 超过 30 行吗？→ 拆成基础版 + 加料版。
3. 有未教概念吗？→ 有就删掉或回教案补教学。
4. 改写点是否"只改一处就有 visible 变化"？→ 没有就加。
5. 注释是中文口语吗？→ 术语注释改成"在干嘛"。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用"循环的 turtle 正方形示例（8-10 岁）"走一遍本 skill，
检查是否 ≤30 行、注释是否中文、是否真实可运行、有无未教概念。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-kids-code/issues。
