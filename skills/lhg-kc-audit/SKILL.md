# lhg-kc-audit：教案自查与安全审查

> **安全声明（必读）**：本 skill 是**家长/老师的备课助手**，不直接面向儿童。
> 所有产出内容**必须由成年人审核后**才能用于儿童；本插件**不收集任何儿童信息**。
> 本 skill 的审查不能代替成年人的最终把关——脚本查的是"格式与红线"，
> "讲得好不好、孩子能不能懂"只能由备课的成年人判断。

> 目标：教案发出前，拦住"结构残缺、代码跑不通、超纲、用词不当、缺审核声明"五类问题。
> 核心纪律：**成人审核声明缺失 = 一票否决；不确定的，标出来给人看，不许悄悄放过。**

## 1. 何时使用

- 教案初稿完成后、交付前 → 全量跑一遍
- 只改了示例代码 → 至少跑第 3、6 节
- 收到"这教案哪里不对"的反馈 → 按第 6 节清单逐条定位

## 2. 自查五步（顺序不能乱）

1. **结构**：教案节是否齐全（见第 3 节）——缺节的课上到一半会断。
2. **代码**：示例是否真实可运行、是否超 30 行、有无未教概念（见 `lhg-kc-example` 第 8 节）。
3. **安全**：红线词、超纲概念、个人信息索取（见第 4、5 节）。
4. **语言**：适龄性（见第 6 节）——术语是否断后、句子是否超长。
5. **审核**：文末成人审核声明是否存在、是否要求"先运行验证"（见第 7 节模板）。

## 3. 结构完整性（缺一不可的节）

- [ ] 顶部信息行：年龄段 / 工具 / 课时 / 所处阶段（用-改-创）
- [ ] 教学目标：1-2 条，用可观察动词（说出/改对/做出）
- [ ] 故事引入：≤3 句话 + 1 个提问钩子
- [ ] PRIMM 五步：预测 / 运行 / 探究 / 改写 / 创造（低龄段"创造"可换成"自由玩+分享"）
- [ ] 课堂互动小游戏：规则 ≤5 条 + 时长 + 安全注意
- [ ] 课后练习：必做 1 + 挑战 1
- [ ] 成人审核声明（见第 7 节，一票否决项）

## 4. 超纲概念分级表（原创整理）

按年龄段划分。教案中出现"慎教/不教"栏的概念 → 标 warning，必须由备课成年人确认是否保留。

| 概念 | 5-7 岁 | 8-10 岁 | 11-13 岁 |
|---|---|---|---|
| 顺序、循环（固定次） | 可教 | 可教 | 可教 |
| 条件分支、变量 | 慎教（只用绰号） | 可教 | 可教 |
| 函数（无参数） | 不教 | 慎教 | 可教 |
| 列表、字符串拼接 | 不教 | 慎教 | 可教 |
| 无限循环、while | 不教 | 慎教（必须有出口） | 可教 |
| 递归、面向对象、多线程、正则、算法复杂度 | 不教 | 不教 | 慎教 |

"慎教" = 可以讲，但教案里必须写清"为什么这个年龄段可以讲、怎么讲才不超纲"，
否则按超纲处理。

## 5. 安全红线检查

1. **用词红线**：全文搜索"杀死/血/死掉/鬼/恐怖/打死/笨/跟不上"——
   命中则改写（失败表述换成"我们再试一次"，施压表述删除）。
2. **个人信息红线**：搜索"姓名/电话/住址/照片/身份证/学校名字"——
   教案与练习**不得要求儿童提供**这些信息；签到表之类需求由成年人线下处理，不进教案。
3. **游戏安全**：互动游戏规则里必须有"安全注意"一行；
   低龄游戏不得含投掷、追逐冲撞、细小物件。
4. **不承诺效果**：教案不得写"学完保证学会/变聪明/赢过别人"类承诺；
   效果表述一律换成"试试看""我们一起"。

## 6. 语言适龄性检查

1. **术语断后**：术语原词（如"循环""变量"）首次出现是否在"总结"环节？
   提前出现 → 挪到总结或换成中文绰号。
2. **句子长度**：讲给 5-7 岁的话术单句 ≤15 字；8 岁以上 ≤25 字。超长拆句。
3. **提问质量**：教案里的提问是否多为"如果…会怎样"（开放），而非只有"对不对"（封闭）？
   封闭提问超过一半 → 补开放提问。
4. **无说教腔**："你应该/你必须"出现超过 3 次 → 换成"我们试试/你可以"。

## 7. 成人审核声明模板（文末必备，原创文案）

```markdown
## 成人审核声明

> 本教案由 AI 辅助生成，仅供家长/老师备课参考。
> - 内容须由成年人通读审核、并实际运行验证示例代码后，再用于儿童教学；
> - 不得直接发给儿童照单执行；课堂讲稿请按孩子的实际情况改写；
> - 本教案不收集、不索取儿童的姓名、电话、住址、照片等任何个人信息。
> 审核人：________  审核日期：________
```

缺这节 = blocker，一票否决。

## 8. 人工评审清单（脚本查不到的，人来查）

1. 故事里的类比真是孩子生活里的东西吗？（问一个该年龄段的孩子 10 秒能反应过来吗）
2. 预测环节的"迷惑选项"真的迷惑吗？（太 obvious 等于白问）
3. 改写任务孩子动手 3 分钟内能看到效果吗？
4. 示例代码你（备课的人）亲手运行过吗？
5. 游戏超时有收束话术吗？
6. 课后练习家长陪做需要准备什么？写清了吗？
7. 有没有哪句话你念出来觉得别扭？（别扭 = 孩子听着也别扭）
8. 术语揭晓语放在总结了吗？

## 9. Warning 处理手册（每条 warning 怎么定）

脚本报 warning 不是让你删内容，而是让你做一次"成年人判断"。常见 warning 的处理：

| warning | 先问自己 | 改 / 保留 |
|---|---|---|
| KC-LSN-002 故事引入缺失 | 这节课真的不需要故事吗？（复习课可能不需要） | 复习课可保留并写理由；新课必须补 |
| KC-LSN-004 小游戏缺失 | 纯讲 45 分钟，纪律撑得住吗？ | 低龄段必须补；高龄段可用"挑战赛"替代并写理由 |
| KC-SAFE-001 不当用词 | 这个词换掉后意思变吗？ | 几乎永远选"改"；保留需逐词写理由 |
| KC-SAFE-002 超纲概念 | 对照第 4 节分级表，这个年龄段是"可教"吗？ | "慎教"需在教案写清讲法；"不教"必须删 |
| KC-SAFE-003 索取信息 | 真的需要孩子提供吗？ | 一律删，改由成年人线下处理 |
| KC-CODE-002 缺语言标注 | 补上标注能让脚本做语法检查吗？ | 补上，30 秒的事 |
| KC-HYG-002 待补充残留 | 这节是"下次再备"还是"忘了"？ | 忘了就补；下次再备就先不交付 |

处理纪律：每条 warning 在交付报告里都要有一行结论（改了 / 保留+理由），
没有"已阅"这种结论。

## 10. 反模式（不要这么做）

- ❌ 脚本全绿就宣布"教案没问题了"——脚本只查格式与红线，好不好讲只能人判断
- ❌ 为了过"超纲检查"把概念名换个马甲藏起来——换汤不换药，孩子照样听不懂
- ❌ 审核声明复制粘贴但没真审核——声明是给备课人看的，不是护身符
- ❌ 发现 warning 就删内容凑合——warning 是"让人确认"，不是"让人删除"

## 11. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 五步顺序是否走全？→ 跳步补上。
2. 有 warning 是否都标给了备课人确认？→ 不许悄悄放过。
3. 成人审核声明是否在文末且未被改得面目全非？→ 模板优先。
4. 是否说了"脚本全绿=没问题"？→ 收回这句话。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：拿一份缺"成人审核声明"、含超纲词"递归"（8 岁教案）的坏教案走一遍，
  检查是否一票否决 + 标出超纲。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-kids-code/issues。
